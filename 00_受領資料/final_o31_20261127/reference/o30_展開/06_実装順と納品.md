# 実行順序
1. 現行HEAD、未コミット差分、版差、既存WBSを確認。別作業ブランチ、合成fixture、既存テスト基準を保存。ユーザー実データを使わない。
2. P0安全性。移行・復元・金融・版差を先に確認。重大な失敗があれば次へ進まない。
3. P1右端追加・ナビ・設定・共通操作・画面刷新。個人版で先に完成させ、全画面到達性を確認。既存o29の有効な実装は再利用。
4. P2分類と表示。既存のカテゴリ操作を拡張。過去の金額と分類を回帰。
5. P3資格・教材・学習。小さく本棚→記録→タイマー→計画→推薦の順。外部取得は規約と費用を確認するまで保留。
6. P4目標。既存条件を保護し、階層・参照実績・計画を追加。
7. P5自由記録・集計。2用途で実証し、汎用化の費用対効果を評価。過剰な汎用フレームワークは作らない。
8. P6性能・品質。npm run checkを両版で実行。独立レビューでデータ・金融・UX・日本語・版差・セキュリティを確認。未解決重大事項はリリース停止。
各IDの作業開始前に現行実装を確認し、実装済/部分/未実装/矛盾/不要/承認待ちを記録。不要の理由と代替を明示。完了はコード位置・試験ID・結果・証拠で示す。1段階ずつコミット、既存作業を上書きしない。
納品：変更ソース、差分台帳の状態、実装前後の全画面写真、アーキ図、移行/復元試験、両版テストログ、性能環境と測定値、日本語監査、残論点、実機確認項目、最新STATE/WBS/ISSUES/DECISIONS/RAID。公開・push・課金・外部送信は別承認。
