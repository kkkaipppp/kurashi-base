# データ契約（論理責務。物理テーブルの新設を強制しない）
既存AppData schemaVersion 2、Transaction/Event/Task/Goal/StudySubject/StudyLog/Category等を正本とする。個人IDBと公開localStorageの境界を守る。新しい型は必要性をADRで判断。既存store操作を拡張し直接保存を増やさない。
- NavigationPreference: version, ordered route IDs, favorite add IDs, start route。端末設定。未知IDを除外し安全な既定へ。記録のバックアップとは区別し、設定出力を提供する場合は明示。
- Category: 既存id/kind/order/archived/role維持。parentId/color/aliases/favoriteは任意候補。金融種別を跨ぐ親子禁止、循環禁止。role未設定の旧カテゴリは変更前の判定を確定させてから改名等を行う。既存の取引側分類保持ロジックを確認。
- Tag/TypedRelation: 安定ID、対象種別、関係種別。表示リンクと金額配賦を分離。配賦合計は純額以下。複数リンクで全体合計を増やさない。
- StudyBook: 現行は資格内のid/title/url/note。教材マスター（版/ISBN任意/種類/状態）と資格リンクを候補にする。移行は旧資格ID＋旧教材IDの対応表を作る。同名自動統合禁止。
- StudySession/StudyLog: 開始/終了/休止、分数、教材参照、分野、演習結果、記録日。既存手入力ログは開始時刻不明のまま。開始・終了の再送を操作IDで冪等化。時間の全体集計はログID集合、重複時間は別途警告。
- GoalCondition: 目標ID、条件種別、単位、期間、比較、閾値、実績源、定義版。旧number/checkはそのまま再現。子目標と条件を別管理。欠測を0としない。手動実績と参照実績を混ぜない。
- CustomDefinition/Field/Value: 定義ID・版、項目ID、型、単位、値。型変更は新しい版、旧値保持。削除は非表示を基本。任意コード・HTML・数式実行禁止。自由金額は金融記録ではない。
- SavedQuery/View: 許可された条件・表示形式・集計指標のみ。金融計算はledgerCore等既存の正本。表示は派生値、保存データに二重計上しない。
移行：旧バックアップ取得→検証→別領域に変換→件数/ID/リンク/金額/時間/版を照合→切替→再起動確認→旧領域保全。失敗時は旧データを残す。旧コードへの巻戻しで新記録を上書きしない。既存20MB復元上限と大規模データを検証し、対応容量を明示。
