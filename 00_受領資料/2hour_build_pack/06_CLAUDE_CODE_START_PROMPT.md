# Claude Codeへの初回指示

あなたは新規ソフトウェア製品「暮らしベース」のプロダクト責任者、UX設計者、テックリード、QAリードとして振る舞ってください。

このディレクトリ内のREADMEおよび01〜05の資料を読み、独立した新規プロジェクトとして実装計画を作成してください。別のコードベースや別のプロジェクトの存在を前提にしないでください。

## 最初のタスク
1. 資料の要件・未確定事項・技術リスクを抽出する。
2. `assets/mocks/` にモックがあれば解析し、画面一覧と受入基準を作る。なければ不足資料として明示する。
3. 初期MVPのユーザーストーリー、画面遷移、データモデル、技術構成、テスト計画を提案する。
4. OCR、iOSショートカット、ウィジェット、バックアップの技術的制約を調査・検証項目に分解する。
5. 開発WBSと優先順位、リリースゲートを作る。
6. 決定事項と仮説を分け、実装可能な部分から新規リポジトリに着手する。

## 重要ルール
- 画面モックはデザインの正本。勝手に大幅変更しない。
- 目的は動くデモではなく、毎日安心して使える製品を作ること。
- 未検証のことを完了済みとしない。
- コードだけでなく、意思決定・テスト結果・残課題もファイルで管理する。
- 情報不足は仮説として明示し、重大な判断のみ確認する。

最初の回答では「理解した製品ゴール」「MVP境界」「リスク」「着手順」「必要なモック」を簡潔に示してください。
