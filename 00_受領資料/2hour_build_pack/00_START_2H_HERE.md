# Claude Code: 2時間集中・新規アプリ構築指令

このディレクトリを完全に独立した新規Webアプリとして実装する。既存プロジェクトのソース、Git履歴、旧データへのアクセスや移行は不要。製品名は「暮らしベース」。資料内の「再現」「旧版」等は成果物に表示しない。既存の参考SVGは**デザイン方向のラフ**であり、元アプリの実画面の忠実なコピーではない。

## ミッション
**目標所要時間120分（保証ではなくタイムボックス）**で、スマホ優先の見栄えのよい、実際に操作できるローカルファーストのWebアプリを作る。制限時間で未完なら動く成果物を残し、未完を明示する。完成を偽らない。質問は環境起動が不可能な場合だけに絞る。

## 実行開始
1. まずこのファイルと README.md、01〜04、07〜10、13、15、16を読む。参考画面は `assets/reference_mocks/*.svg`。他の仕様との衝突は本ファイルと15/16を優先。
2. 実装環境を確認。未作成なら Next.js + TypeScript + Tailwind CSS で新規作成。既存ディレクトリを壊さず必要なサブディレクトリに構築する。可能なら `app/` 直下に配置。
3. 最初の15分で起動できる画面を用意し、以後は各工程ごとに実際に動く状態を維持。
4. 次の順に実装し、終わるたびにビルド/型チェック/簡易テストを実行。エラーはその場で直す。
5. 最後に `DELIVERY_REPORT.md` を書き、実装/未実装、実行コマンド、テスト結果、次の改善候補を報告。

## 120分の作業配分（目安）
- 0〜15分: セットアップ、起動、ナビゲーション、テーマ
- 15〜40分: ホーム、カレンダー、支出入力、収支集計の見た目と導線
- 40〜70分: 取引CRUD、予定CRUD、永続保存、入力検証
- 70〜90分: 固定費、カテゴリ、月次集計、フィルタ
- 90〜105分: 画像取込画面、OCRの実現可能な最小実装、重複候補表示（不可能なら手入力確認フローを完成）
- 105〜120分: バックアップ書出/復元、重要テスト、修正、納品レポート

## 絶対優先するP0
- スマホ幅375pxでホーム/カレンダー/支出追加/予定追加が破綻せず操作可能
- 支出・収入の追加/編集/削除、予定の追加/編集/削除、月別集計
- リロードしてもデータが消えない。保存失敗時に成功と表示しない
- 支出と予定が同じ日付軸で確認できる。空状態も自然
- 入力バリデーション、削除確認、二重送信防止、ローカル日付のズレ防止
- `npm run build` 成功（または原因を報告）

## P1（時間内で可能な限り）
- 固定費の繰り返し設定・次回予定表示、カテゴリ管理、支出検索/絞込
- JSONバックアップとプレビュー付き復元、重複候補の警告
- OCR：無料のクライアントサイド手法が短時間で安全に導入できるなら実装。抽出結果は必ず確認編集してから保存。できなければ画像プレビュー＋手入力確認導線を提供し「OCR実装済み」と言わない

## P2（後続改善）
- OCR高精度化/3,000枚学習、iOSショートカット通知連携、ネイティブウィジェット、クラウド同期、共有、資産/契約/健康などの追加領域。P2を無理に作ってP0を壊さない。

## UI品質
参考SVGの情報設計を起点に、モバイルアプリらしい高品質UIに整える。余白・タイポグラフィ・階層・タップ領域・選択状態・ローディング/空状態を丁寧に。主要操作は1〜2タップ。ホーム主要情報は「今月の残り」「今日の予定」「支出追加」「画像取込」。補助情報は設定でON/OFF可能にする（余裕があれば）。ダミーデータを本番データとして混入させない。

## 禁止事項
- モック画像だけを表示して実装済みと報告しない
- OCR、通知自動取得、ネイティブウィジェットを未実装なのに完成と称さない
- 未テストなのに全テスト合格と書かない
- 外部有料APIや秘密鍵を必須にしない
- 指示を読んだだけで作業を止めない。ファイルを編集し、実行し、検証する
