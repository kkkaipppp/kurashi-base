# 受入テスト仕様・リリースゲート

## 判定ルール
- テスト結果は `PASS / FAIL / BLOCKED / NOT RUN` で記録。未実行をPASSとしない。
- P0: データ損失・誤集計・プライバシー漏えい・主要操作不能。P0はゼロ必須。
- P1: 主要フローの不具合。ベータ公開前に原則ゼロ必須。
- テストの実施環境、ビルドID、日時、手順、期待結果、実測、証跡、担当を残す。

## OCR精度評価（別ゲート）
- 画像セットを店舗・決済画面・レシート・暗所・複数金額・返品・個人情報マスク済みで層別する。
- 金額・日付・店名それぞれの完全一致率、候補提示率、修正時間、誤確定件数を記録する。
- 目標閾値は評価データを確認して決定。画像3000枚の収集・学習済みと主張しない。権利と個人情報を確認したデータのみ利用。

## ベータ版リリース条件
1. AT-001〜024のうち対象MVPテスト実施、P0/P1の未解決ゼロ。
2. 実機相当のiOS SafariとPCブラウザで主要フローを確認。
3. バックアップ・復元の往復検証と復元失敗時の保全検証を完了。
4. モック比較結果、既知制約、プライバシー説明、利用者向け簡易操作案内を整備。
5. iOS通知自動取得・ウィジェット等の未実装機能は明示し、提供済みと表示しない。
