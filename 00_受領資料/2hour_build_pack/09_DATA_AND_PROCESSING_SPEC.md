# データ・処理・例外仕様

## 論理エンティティ
| エンティティ | 主キー・主な属性 | 関連・制約 |
|---|---|---|
| Transaction | id, type, occurredAt, amountMinor, currency, categoryId, merchant, paymentMethodId, note, source, sourceFingerprint, createdAt, updatedAt | 金額は整数、typeで収入/支出を区別 |
| Event | id, title, startsAt, endsAt, allDay, note, categoryId | 開始 <= 終了、日跨ぎを許容 |
| Category | id, name, kind, order, archived | 削除時の既存取引との整合性を維持 |
| Budget | id, period, amountMinor, scope | 対象範囲を明記し、月次集計と整合 |
| RecurringExpense | id, name, amountMinor, cycle, nextDueDate, active, categoryId | 予定は実支出と別、月末規則を明記 |
| ImportCandidate | id, imageFingerprint, extractedFields, confidence, status, createdAt | 未確定は集計に含めない |
| DisplayPreference | id, key, enabled | 再起動後も保持 |
| BackupManifest | schemaVersion, exportedAt, counts, checksum | 復元前に形式・整合性を検証 |

## データ処理原則
- すべての更新を一貫したトランザクションとして扱う。途中失敗で半端な保存を残さない。
- 内部時刻は一貫した形式で保持し、ユーザー向け日付表示・月次集計のタイムゾーンを固定または設定可能にする。
- 表示集計は確定取引のみを対象とする。候補・固定費予定・削除済みを混入させない。
- 取引の変更はホーム、カレンダー、カテゴリ別集計へ反映する。
- 初期はローカルファーストを候補とするが、保存基盤は実装前にADRで確定。ブラウザ保存の限界をユーザーへ説明する。

## 画像取込ステート
`選択 → 読取中 → 候補表示 → 編集・重複確認 → 確定保存`。別経路として `読取失敗 → 手入力`、`取消 → データ未保存`。
- 金額複数候補：合計を優先候補として表示しても、ユーザーが最終確認する。
- 日付不明：現在日付を事実として自動確定しない。
- OCR不明瞭：不明フィールドを強調し、編集できる。
- 同一画像：指紋で警告。類似画像・同額別取引は追加確認。

## 重複判定の設計
- 完全一致候補：同一指紋または同一外部ID。
- 類似候補：金額一致、日付近接、店舗正規化類似、決済手段等の複合スコア。
- 閾値はテストデータで評価し、精度を測定して調整。閾値を根拠なく確定しない。
- 誤検知の損害を避けるため、検出は警告にとどめ、自動削除・自動統合しない。

## バックアップ・復元
- 書出形式はバージョン付きJSON等を候補とし、機微情報の保護、ファイル名、サイズ、整合性を検証。
- 復元は `選択 → 検証 → プレビュー → ユーザー確認 → アトミック反映 → 件数照合`。
- 既存データへの上書き／追加は明示的選択とし、ID競合・同一データの扱いを仕様化。
- バージョン不一致、破損、容量不足、途中中断のいずれでも既存データを保持。

## セキュリティ・プライバシー
- 収支、予定、画像、健康などの機微情報を外部サービスへ送る場合は目的・送信先・保存期間を明示し同意を得る。
- 画像に含まれる氏名、カード情報、注文番号等をテスト・ログ・解析へ無断収集しない。
- 将来の複数端末同期や共有は認証・権限・競合解決の設計後に着手する。
