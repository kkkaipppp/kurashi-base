# 5. はじめて使う人に合わせた日本語と導線

## 最初の60秒
1. ホームに「今月の残り予算」「今日の予定」「今日やること」。ゼロ件は空の説明を長く並べず、1つの主行動を表示。
2. 主要行動は画面下の「＋」。支出→金額→カテゴリ→保存の最短ルート。補足は詳細欄に収める。
3. バックアップは「設定」に配置しつつ、初回の導線で説明。`iPhoneのファイルアプリで保存先を確認` を明示。
4. 新機能10領域はメニューにまとめ、ホームへ無理に詰め込まない。

## 既存コードの文言改善候補
| 画面 | 現状 | 改善案 | 理由 |
|---|---|---|---|
| 設定・保存 | `すべてのデータを削除` | `この端末の記録をすべて削除` | 削除範囲を明確化 |
| 設定・復元 | `直前の操作を取り消す` | `復元前の状態に戻す`（適切な状態の場合） | 操作対象を明確に |
| 設定・復元 | `反映のしかた` | `復元方法を選ぶ` | 普通の言葉で操作を表す |
| 予定詳細 | `Googleカレンダーで予定を作る` | 維持 | 同期ではないことが分かる |
| 予定詳細・補足 | `予定名・日時・場所だけを渡します…` の長文 | `Googleカレンダーが開きます。確認して保存してください。` | 詳細情報は折りたたみ、必要な人だけ見る |
| 保存失敗 | Safariのサイトデータ削除を案内 | `まだ削除しないでください。先にバックアップを保存してください。` | 操作ミスによる本当のデータ消去を防ぐ |

## 最も重要なUX欠陥
`app/src/lib/storage.ts:60,83` に「Safari の使っていないサイトのデータを消してください」という案内があるが、ユーザーが誤って**このアプリのサイトデータを消してしまう**可能性がある。保存できないときは先にJSONバックアップを案内し、Safariのサイトデータ削除を直接指示しない方が安全。

## 人による確認
- UI確認に使うテストデータは架空のもののみ。
- 友人に説明せずURLを送り、支出1件登録・予定1件登録・予算の場所の理解・バックアップの保存先の理解を観察する。
- 「説明を読まなかった」「ボタン名が伝わらなかった」を操作の欠陥として記録し、ヘルプ文章を増やす前にUI側を修正。
