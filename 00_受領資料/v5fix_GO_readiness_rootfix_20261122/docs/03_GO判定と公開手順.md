# 3. β公開GO判定と公開手順

## 判定ロジック
- **GO**：基準コミットの修正を反映したビルドで `npm ci && npm run check` 全合格、追加テスト実行、B01〜B15全件PASS、保存と復元をiPhone Safariで実証、公開URLの動作・プライバシー案内・友人への対象範囲説明が完了。
- **NO-GO**：上の必須項目にFAIL/NOT_RUN/BLOCKEDが1つでも残る。報告だけの「PASS」や古い画面の証拠は合格としない。
- GOは**友人1人・1週間の試験公開**に限る。一般販売や正式公開のGOとは別。
- 0件の不具合を証明することはできないため「完璧」を宣言しない。発見可能な重大リスクを除去して客観的なGOを出す。

## Claudeの自律ワークフロー
1. 作業ブランチ作成。元データとGitの復旧地点を記録。
2. パッチ適用前に新テストのREDを確認。既存テストは保持。
3. コード修正・Vitest GREEN・既存160件と追加の回帰テスト・Lint・TS・ビルド確認。
4. 同一レコード編集の競合ガードを予定以外（取引、旅行など）に順次展開。テストで同様の上書きがないことを検証。
5. 実画面をブラウザで確認し、日本語を短くして初見ユーザーの操作を最優先。
6. Vercelのプレビュー環境を用意する場合、**既存公開を勝手に切り替えない**。公開操作・公開先選択はユーザーの承認に従う。
7. `docs/release/GO_EVIDENCE_YYYYMMDD.md`にテスト結果、バージョン、実機結果、スクショ、URLをまとめる。
8. B01〜B15が完了したらその証拠に基づきGOを判定。未実施なら正直にNO-GOとする。

## ロールバック
- 固定の公開URL・Gitのコミットハッシュ・バックアップJSONを残す。
- 以前のコードに戻す場合、現行v2データと新旧画面の互換をテストする。ユーザーの記録自体を上書きしない。
- ビルド失敗、データ消失、復元失敗、保存不能の再現があれば配布停止。復旧案内を友人に伝える。

## 公開範囲
- GitHub Privateはソースへのアクセス制限であり、Vercelの公開URLへのアクセス制限ではない。
- `noindex`は検索抑制であり認証ではない。1人にだけ見せたいなら別途アクセス制御の要件が必要。
- 同じアプリでもプレビューURLと本番URLはオリジンが異なり、localStorageは共有されない。
