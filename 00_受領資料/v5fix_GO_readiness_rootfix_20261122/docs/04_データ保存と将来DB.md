# 4. データ保存は大丈夫？（現状評価と将来方針）

## 今の実態
- 現行は**データベースではなく、ブラウザのlocalStorage**。`kurashi-base:data:v1` に `schemaVersion=2` のJSON一式を保存する。
- ユーザー認証、クラウド同期、サーバー側の保存・復旧はない。別端末・別ブラウザ・別オリジンには記録を引き継がない。
- v1→v2 の移行・復元と取り消しの仕組みはあるが、保存できること自体を永続保証するものではない。
- 容量不足、プライベートブラウズ、サイトデータ削除、端末故障、SafariのWebサイトデータ保持ポリシー等で記録を失い得る。
- SafariのITPによるスクリプト書込み可能ストレージの保持制約はサイト利用状況・条件によって影響する。単純に「7日間必ず安全」とは言えない。

## 友人β（1人・1週間）での判断
- **DB新設は必須ではない。** 単一端末で短期間、試用データに限り、復元検証と本人のバックアップを条件に運用可能。
- アプリに「この端末・このブラウザだけ」「定期バックアップ」「ブラウザデータ消去で消える」の説明を出す。
- β期間の最初と最後にバックアップし、可能なら複数の安全な保存先に控える。
- βで重要な個人データを預ける設計を売り文句にしない。

## 一般向け販売までの必須検討（後続フェーズ）
- アカウントとデータの所有者管理、認証・権限、バックエンド保存、端末間同期、暗号化（転送・保存）、監査・ログ、削除請求対応。
- ローカル→クラウドの移行で二重化しないID戦略、競合解決、オフライン時のキュー、トランザクションの整合性、復元手段。
- PostgreSQL等のリレーショナルDBや管理型バックエンドは候補。**いまこのZIPで実装製品・サービスを決め打ちしない。**
- 既存の`STORAGE_KEY`と`schemaVersion=2`を変えずに追加移行する方針を検討する。いきなりschema変更せず、双方向の互換テストと移行バックアップを先行。

## 本番開始前の結論
**友人β：条件を満たすなら現行localStorageで実施可能。正式販売：現行ままではデータの安全・同期・復旧の期待に十分応えられないため、クラウド永続化を含めた再設計が必要。**
