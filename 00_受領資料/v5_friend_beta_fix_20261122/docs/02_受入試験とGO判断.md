# 友人β（1人×1週間）のGO条件

## 自動検証（必須）
1. v5で報告済みの147件＋ `beta-final-guard.test.ts` の追加ケースをPASS。
2. `cd app && npm ci && npm run check` が型・lint・テスト・ビルド含めて全成功。
3. v1/v2バックアップの全置換・追加復元・取り消し/やり直しが正常。
4. 旅行IDの意味衝突があるとき、関連行程が誤紐づけされない。
5. 場所・URL・持ち物・旅行・費用など「編集で消す」が永続的に反映される。
6. 保存失敗時にデータを失わず、元に戻せる控えを失わない。

## iPhone Safari 実機（未実施はPASSにしない）
- 予算設定→支出→ホーム反映→アプリ再起動後も同じ金額。
- 予定作成→詳細を入れる→詳細を消す→再起動後も消えたまま。
- カレンダー日付から予定を登録。日付が継承される。
- バックアップ書き出し→ファイルアプリ確認→復元プレビュー→置換→取り消し→やり直し。
- キーボード表示中も保存ボタンがタップできる。日付入力が操作できる。
- Chromeなど別ブラウザではデータが共有されないことを事前説明。
- 公開URL（Vercel等）で同一URLを使い、ドメイン変更でデータが別になることを確認。

## ユーザー視点の初見テスト
- 説明なしでホームから「今月の残り予算」「次の予定」を探す（5秒以内が目標）。
- 予算を設定→支出を1件登録（初見60秒以内を目標）。
- 予定を作り場所を追加→Googleマップへ移動。
- 「Googleカレンダーで予定を作る」の動作が同期でないことを理解しているか確認。
- テスト後に迷った箇所を本人の言葉で記録し、P0/P1に振り分ける。

## 判定
- P0なし、自動チェック全PASS、iPhone保存・復元・undo一連の試験PASS、最低限の初見操作確認 → GO（友人1人×7日）
- それ以外 → NO-GO。未実施は未実施として報告する。
- 友人5人公開・一般公開・課金開始は別判定。
