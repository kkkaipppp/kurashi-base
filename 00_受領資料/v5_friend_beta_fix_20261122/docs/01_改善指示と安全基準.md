# くらしベース v5 beta/friend-v1（2cf3cb5）改善指示

## 依頼の目的
- 現行v5の4つの高優先度不具合を再発しない形で修正し、友人1名・1週間のベータ試用を安全に開始できるようにする。
- 新規機能やDB再設計、配色・レイアウトの総作り替えはしない。
- ローカルストレージキー `kurashi-base:data:v1`、schemaVersion 2 は維持する。

## 重要：このZIPのoverlayは「修正候補」であり、いきなり丸ごと上書きしない
- 現行プロジェクトのコードとの差分を確認し、最新の変更を消さないよう反映する。
- 元のソースは `kurashi-base_v5_brand_2cf3cb5.zip`。コミットが変わっていたらパッチ適用前に差分評価。
- 先に失敗を再現するテストを作成→修正→回帰テスト→実機試験。

## P0-1：予定編集で削除した詳細が復活する
- 原因：`EventSheet.tsx:294-304` で undefined を消し、`store.tsx:160-161` が旧イベントとマージしていた。
- 修正候補： `eventMerge.ts` の `replaceEventEditableFields` を `store.updateEvent` から呼ぶ。全編集フィールドを置換し、id/createdAtのみ保持。
- 合格条件：場所、URL、持ち物、旅行、費用、行程種別を各々空に→保存→画面終了→再起動→空を維持。新規追加と繰り返しは従来どおり。

## P0-2：復元で別旅行に行程がくっつく
- 原因：`backup.ts:149-190` で旅行の意味を比較する前にイベントが取り込まれていた。
- 修正候補：旅行の同一ID・異なる名称/目的地/期間は conflict とし、関連イベントは dependentSkipped でスキップ。`validateRelationships` に tripId の参照先検証を追加。
- 合格条件：京都と札幌の旅行IDが衝突しても北海道旅行の行程を京都へ追加しない。既存記録が不変。全置換は別途正常に動作。
- TODO：より進化させるならUUIDを再発行して行程を安全に再紐づけ。ただし本βでは勝手に書き換えるよりスキップを優先。

## P0-3：容量不足で既存データまで開けない
- 原因：`storage.ts:19-32` の読み込み前の保存可否プローブ。
- 修正候補：読み込み前の書き込みテストを撤廃。書き込み可否は実保存時に検出。
- 合格条件：quota超過でsetItemが失敗してもgetItemが読める場合、ホーム・履歴・バックアップ書き出しを利用できる。保存は失敗を明確に表示。
- 手動確認：ブラウザで疑似quotaエラー。iPhone実機は別途。

## P0-4：復元失敗で取り消し履歴を失う
- 原因：`storage.ts:117-134` が先にUNDOを上書きし、本体保存失敗時に元へ戻していない。
- 修正候補：元のundo文字列を保持し、失敗時に復旧。undo復旧失敗時は明確に危険を表示。
- 合格条件：本体書き込みだけ失敗、undoだけ失敗、undo削除失敗、競合、v1控え、やり直しの全ケースを実行。
- 制約：localStorageは複数キーの原子性がない。ブラウザ強制終了の窓を完全にゼロとはできない。より高度な保護は独立の保存方式検討とする。

## P1：ユーザー視点の追加改善
1. 予定詳細の「Googleカレンダーに追加する」は実際には作成画面への遷移。`Googleカレンダーで予定を作る` にする。
2. URL欄エラーがhttpsだけを案内しているがhttpも許可している。案内の矛盾を修正。
3. iPhoneでは予定の新規→追加→編集→任意項目削除を実機で検証。
4. 初見ユーザーに保存とバックアップがローカルブラウザだけであることを案内。
5. 予定リンクと外部URLは、何を渡すか（予定名、日時、場所等）を簡潔に案内する。

## 禁止事項
- 失敗した保存で「保存しました」と表示すること。
- 画像プレビューを実機スクリーンショットと偽ること。
- `check` が走らない環境で合格と報告すること。
- GitHubやVercel本番への無断公開、既存ユーザーデータ削除。
