# 11｜自律的に完成度を高める実行ルール（v5への追記）

## 目的
ユーザーが離席中でも、Claude Codeの権限・セッションが続く範囲で、**計画の作成で止まらず実装→テスト→実機確認項目の洗い出し→修正→WBS更新**を進める。ソースの実行・外部公開をこの文書だけで保証するものではない。

## 開始前
1. 現在の作業ブランチ・未コミット差分・既存の最新実装とテストを確認し、上書きや実データ削除をしない。
2. 元のv5資料（`00_CLAUDEに貼る.txt`, 01〜09）、nested `previous_UX_and_data_quality_pack.zip`、本追加指示10〜11を確認し、優先度を統合する。
3. 既存設計や完成済み機能を尊重し、変更箇所を最小にする。

## 実行順序と優先度
P0 データ保護：保存・復元・取り消し・競合・データ互換性を守る。既知の重大不具合があれば最初に修正。
P0 UX：ホームの3秒理解、予定/支出/収入の短い入力と編集、カレンダー連動、自然な日本語、画面を跨いだ戻る操作。
P1 旅行・資格：複数日旅行、予約・場所・メモ・外部リンク、資格候補検索・学習時間・教材リンクとnote検索。
P1 ブランド：採用方向に沿ったロゴ/アイコン/文言の統一。ホームを複雑にしない。
P2 OCR：ライセンス確認済み評価データの収集、GT検証、再現可能な2,000画像ベンチマークと実装可能なOCR。画像未取得・OCR未実装なら「未実施」を明記。

## 一周ごとにやること
- まず失敗例を再現できる検査・テストを書き、修正し、ビルド/lint/typecheck/既存テスト/追加テストを実行。実際に実行したコマンドと結果を記録する。
- UI改修は「初めて触る人の具体的タスク」と結びつける。例：起動→予算を見る→＋→支出登録→カレンダー→振り返り。押せない導線を作らない。
- UXは短文ラベル、1画面の情報優先順位、タップしやすさ、キーボード表示中の操作を確認。
- 親フォルダのWBS/進捗が存在する場合は更新し、存在しなければ `docs/PROGRESS_AND_NEXT.md` を作成。各タスクに実装済み/テスト済み/実機未検証/保留と理由を付ける。
- 各サイクル終了時に、まだ安全に進められるP0/P1があれば次に進む。説明文だけ書いて終わらない。

## 判断が必要な時
- 一般的なUI/実装の選択は根拠を記録し自律的に進める。
- 外部公開、課金、実データの削除、資格の数値や教材の架空生成、ライセンス不明の大量画像取得、アフィリエイトタグの無断設定は**実行しない**。
- 権限・実行時間・依存関係・機密情報で阻まれた場合は回避策を検討し、実施できない作業を残タスクとして記録する。実行できない作業を実行済みにしない。

## 最後に残す報告
- 何を実装し、どのファイルを変更し、何が見えるようになったか
- `npm run check` の実結果／未実施理由、追加テスト数と落ちたケース
- 画面・ブランド・日本語の改善前後と、iPhone実機の未確認項目
- OCRデータセットの実取得枚数、利用条件、評価結果、実施していないこと
- 公開GO/NO-GO判定と未完了の優先度、次の再開コマンド
