## 1. 何を外に置くか【案】
外に置くのは、回答のリンクに要るものだけ。家計・予定の本体、ほかの計画、メモは端末から出さない。

| 置くもの | 中身 | 置かないもの |
|---|---|---|
| 調整（poll） | 名前（計画の名前を、送る前に直せる）・候補日（日付と「昼」「夜」などの短い言葉）・締め切り・作った日・消す予定日 | 計画の id・場所・予算・メモ・参加者の連絡先 |
| 回答（answer） | 表示名（20字まで・本名でなくて良い）・候補ごとの ○△×・一言（50字まで・任意）・回答した日 | メール・電話・端末の情報 |

- 送る前に「この内容をネットに置きます」と、置く中身をそのまま見せて、押したときだけ送る
- 計画の名前は、そのまま送らず、送る前の画面で直せるようにする（「〇〇さんの誕生日」などを避けたいとき用）

## 2. 形【案】
```
polls/{pollId}            … pollId は推測できない長い乱数（リンクに入る）
  title, options[{id,label}], closesAt, createdAt, expiresAt, ownerKeyHash
polls/{pollId}/answers/{answerId}
  name, marks{optionId: "o"|"m"|"x"}, comment?, createdAt
```
- 持ち主（平尾さん）の操作（締め切る・消す）は、作ったときに端末に持つ秘密の鍵で確かめる。外には鍵そのものではなく、その鍵から作った値（ハッシュ）だけを置く
- 回答者はアカウント無し。Firebase の匿名ログイン【事実：Firebase Auth にある】を使い、自分の回答だけ直せるようにする案と、直せない（出し直し）案がある → 論点 S-3

## 3. 守り（セキュリティルール）【案】
- 誰でもできるのは「リンクを知っている調整の読み」と「回答の追加」だけ。調整の一覧は取れない（list を禁止）
- 回答は、項目の名前・字数・○△×の値・候補の id を、ルールで決まった形だけ通す
- 締め切り後・消す予定日の後は、書けない
- App Check【事実：Firebase にあり、正規のアプリからの呼び出しかを確かめる】で、アプリ以外からの書き込みを減らす
- **ルールの試験を先に作る**（Firebase のエミュレータを手元だけで動かす。外に送らない）。比べた資料の「ルールを間違えると誰でも書ける」の弱みへの手当て

## 4. 費用と止まり方【事実は比べた資料から】
- 無料の Spark のままにする。超えたらその月の残りは止まり、自動では課金されない【事実】
- 有料（Blaze）に上げない。上げると予算アラートは通知だけで止まらない【事実】
- 止まったとき、アプリは「回答のページが今は開けません」と出し、端末の計画は今までどおり使える【案】

## 5. 置く場所と消し方【案】
- Firestore の場所は東京（asia-northeast1）。後から変えられない【事実】ので、作るときに一度で決める
- 保存期間：締め切りの 30 日後に消す（論点 S-2）。Firestore の TTL（期限が来た文書を自動で消す機能）を使う案。TTL の消し方と無料版で使えるかは作る前に確かめる【未確認】
- 計画を消したら、調整と回答も消す（持ち主の鍵で消す）
- 友達への説明：「回答は Google のクラウド（東京）に置き、締め切りの 30 日後に消えます」

## 6. アプリ側【案】
- 自分用だけ（公開版の組み立てに入れない。`NEXT_PUBLIC_KB_EDITION === "personal"` で切る）
- 端末の計画に `shareId` などを足すと保存の形が変わる → `migrate()` と試験が先、平尾さんの OK が要る
- 回答は自動で計画に入れず、「回答を見る」→「この日に決める」を押したときだけ反映する

## 7. 平尾さんに決めてもらうこと（どれも承認が要る）
- S-1 Firebase で良いか（伝言の「そうふる」の確かめ）。アカウントとプロジェクトは平尾さん本人が作る
- S-2 回答の保存期間：①締め切りの 30 日後 ②締め切りの 7 日後 ③持ち主が消すまで
- S-3 回答者が自分の回答を直せるか：①直せない（出し直し・簡単） ②匿名ログインで直せる
- S-4 計画の名前を外に出す前に直す画面を入れるか：①入れる ②入れない
- S-5 保存の形の変更（計画に共有の印を足す）と npm パッケージ（firebase）の追加
