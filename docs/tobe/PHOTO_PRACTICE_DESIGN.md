# 写真の添付と練習用のデータ（設計案・2026-11-28）

## 1. 写真の添付（メモ・書類・レシート）

### 何が問題か
- 記録は端末の中（IndexedDB。古い端末は localStorage）にだけある。写真は1枚で数百KB〜数MB。localStorage は 5MB ほどしか入らず、写真を入れると、ふつうの記録が保存できなくなる。
- バックアップ（JSON）に写真を入れると、ファイルが大きくなり、復元や iPhone の共有で失敗しやすくなる。
- iPhone は容量が足りないと、Web の保存（IndexedDB）を消すことがある。前の点検で「消えたら知らせる」仕組みは入れたが、写真が増えるほど消されやすくなる。
- 要件 03「書類添付未対応なら保管場所のみと明示」。

### 案
- **① 保管場所だけ書く（おすすめ・小さい）**
  - メモ・書類に「写真の保管場所」の欄（例：iPhone の写真「レシート」アルバム）を足すだけ。写真そのものは持たない。
  - 容量・バックアップに影響しない。使い方に「写真は iPhone の写真に置いてください」と書く。
- **② 写真を IndexedDB に別に置く（中）**
  - 記録とは別の入れ物に、縮めた写真（長い辺 1280px・JPEG）を置く。記録には写真の ID だけ。
  - バックアップは「写真なし」と「写真あり（別ファイル）」を選ぶ。容量の表示と上限（例：合計 200MB）。
  - 試験：容量不足・写真だけ消えたとき・復元で写真が無いとき・別タブ。
- **③ iPhone アプリの中のファイルに置く（大）**
  - Capacitor の Filesystem に置く。iPhone アプリだけ（Web 版は①）。npm の追加（@capacitor/filesystem）が要る。

### 判断してほしいこと
- 写真をどこに置くか（① / ② / ③）。②③は保存の形の変更（記録に写真の ID）。③は npm の追加。

## 2. 練習用のデータ（使い方を試す）

### 何が問題か
- 記録の保存の先は1つ（IndexedDB）。練習のときに同じ保存の先を使うと、本当の記録を上書きする。
- 記録を書いたときに、ほかにも写しを作る仕組みがある：
  - 自動バックアップ
  - iPhone のウィジェットの要約
  - iPhone のカレンダーへの書き出し
  - 通知
  - 直前の操作の取り消しの控え
  
  練習の中身がこれらに入ると、本当の記録の控えを練習の中身で上書きする。

### 案
- **① 練習は、保存しない（おすすめ）**
  - 「練習を始める」と、見本のデータを持った**保存しない保存の先**（メモリーだけ）に切り替える。閉じる・「練習をやめる」で消える。
  - 練習の間は、自動バックアップ・ウィジェット・カレンダー・通知・取り消しの控え・バックアップの書き出し・復元・すべて削除を止める（ボタンも出さない）。
  - 画面の上に「練習中（本当の記録とは別。保存しません）」の帯をいつも出す。
  - 試験：練習の前後で本当の記録が1バイトも変わらないこと・ウィジェットとバックアップが書かれないこと・別タブで本当の記録を開いているとき。
- **② 練習を使い方の画面の中だけにする（小）**
  - 使い方の画面に、動く見本（記録を持たない部品）を置く。本当の画面では練習できない。

### 判断してほしいこと
- ① 本当の画面で練習（保存しない）か、② 使い方の中の見本だけか。①は保存の仕組みに手を入れるので、データを守る点検（kurashi-data-safety）を必ず通す。
