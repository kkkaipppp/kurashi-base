`tools/ocr_benchmark/acquire.py` が取りに行く2つのデータを確かめた。

| | CORD v2（naver-clova-ix/cord-v2） | nano-receipts（34data/nano-receipts） |
|---|---|---|
| ライセンス | CC BY 4.0。HF の項目と GitHub の LICENSE-CC-BY が一致 | MIT。HF の説明文に書いてあるだけ。LICENSE ファイルは確認していない |
| 商用での利用 | 禁止の条項はない（CC BY は商用も可） | 説明文に「商用・非商用とも可」と書いてある |
| 表示の義務 | あり。作者・ライセンス・元の URL・手を加えたことを示す | 説明文には書いていない（MIT の一般論としては著作権表示を残す） |
| 個人情報 | 店の情報・支払いの情報の項目はインドネシアの法律上の理由で消してある。肖像などの権利は許諾の外 | AI で作った架空のレシート。ただし実在の店名（Walmart など）を使っている可能性があり、扱いは書かれていない |
| 出どころ | 論文つき（Park ほか 2019）。出どころは確か | 作った人・元の手順が公開されていない。説明文の言い分だけが根拠 |
| ログイン・同意 | 不要（画面上は） | 不要（画面上は） |
| 枚数・大きさ | 1,000枚（学習800・検証100・テスト100）、約2.3GB | 2,428枚、約2.9GB |
| 言語 | インドネシアのレシート（インドネシア語と英語、ルピア） | 書かれていない。店名から英語（米国）と推測 |
| 正解データ | あり（精度を測れる） | なし（壊れずに動くかの確認だけ） |

## 分かったこと
1. **どちらも日本のレシートではない。** 縦書き・全角・「¥」・税込の表記は入っていない。この2つで測った精度は、くらしベースの利用者（日本のレシート）の精度の目安にならない。
2. CORD v2 は、表示の義務を守れば使える。画像はリポジトリに入れない（`.ocr-eval-data/` は .gitignore）。
3. nano-receipts は、出どころが説明文だけで弱い。使うなら「動作の確認だけ」にとどめ、結果を外に出す資料には使わない。
4. 取ると合わせて約5GB。ダウンロードと Python の datasets ライブラリの導入は、平尾さんの OK が要る（まだしていない）。
