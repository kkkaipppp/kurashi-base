# ADR-001 技術スタックと保存方式（2026-11-21）

## 決定
- Next.js 16（App Router）+ TypeScript + Tailwind CSS v4。全画面をクライアントコンポーネントとして作り、サーバー処理は持たない。
- 保存先はブラウザの localStorage。アプリ全体のデータを1つのJSONとして、1回の書き込みで保存する（schemaVersion 1）。
- 日付は端末ローカルの `YYYY-MM-DD` 文字列、時刻は `HH:mm` で持つ。`toISOString()` は使わない（UTC変換で日本時間の前日になるのを防ぐ）。
- 金額は円の正の整数。収入/支出は `type` で区別する。
- 単体テストは vitest。E2E（Playwright）は、ブラウザ本体のダウンロードが大きいため Phase 1 では入れず、アプリ内ブラウザでの手動確認で代える。

## 理由
- 資料（00/13/14）の推奨どおり、短期間で動く Web/PWA の土台を作るため。
- データ量が小さい（個人の家計・予定）ため、localStorage の容量（通常5MB前後）で足りる見込み。全体を1回で保存するので、途中で失敗しても半端な状態が残らない。
- 保存に失敗したら画面の状態を更新しない（先に保存し、成功したときだけ反映する）。そのため「保存できていないのに成功と表示する」ことがない。

## 制約と代替案
- ブラウザのデータを消すとデータも消える → JSONバックアップ／復元（チェックサム・プレビュー・追加／置き換えの選択）で補う。
- 端末間の同期はできない → 将来、IndexedDB への移行とサーバー同期を別ADRで検討する。
- localStorage は同期APIで、データが大きくなると遅くなる → 取引が数万件になる頃に IndexedDB へ移る。

## OCR（未決定）
- tesseract.js（端末内で処理、無料）が候補。ただし言語データをCDNから取得するため、配布元・サイズ・日本語の精度を検証してから決める。Phase 1 では「画像を見ながら手で入力する」流れだけを提供する。
