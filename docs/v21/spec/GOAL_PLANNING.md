# v4 目標から実行への統合設計
2026-11-24 / d756cbc。予定・タスク統合と目標の構造化・サジェストはユーザー承認方針。以下の具体仕様は設計提案であり実装未済。v3の保護条件を維持。

## UXとドメイン
- 独立タスク画面・登録入口を新設しない。既存タスク導線は予定の「日付未定」「期限あり」「完了管理」フィルタへ移行。開始・終了・期限・完了は独立属性。完了不要の予定も許容。
- 目標→達成条件（成果指標）→マイルストーン→行動計画→予定→実績→見直し。目標なしの予定も許容。行動計画は繰り返し予定の生成元であり別のタスク台帳ではない。
- Goal: id,title,why,targetDate,status; Metric: goalId,unit,baseline,target,direction,observations; Milestone: goalId,criterion,due; ActionPlan: goalId,milestoneId,frequency,duration,estimatedCost,dependencies; 既存予定IDへの関連を保持。型名は仮。複数目標への関連は参照のみ、時間・費用の集計を重複させない。
- 成果進捗は基準値から目標値までの変化。方向・単位・基準値同値・欠測・定性目標を扱う。行動進捗は実績/計画。成果と行動を混同しない。未測定は未測定表示。完了チェックから学習時間や成果を捏造しない。

## 提案エンジン
1. 目標の種類、期限、現状、利用可能時間・予算を任意入力。未入力でも下書き可。
2. 無料のローカルテンプレート（資格、貯蓄、旅行、習慣、自由目標）から達成条件・行動・頻度・所要時間候補を生成。自由目標は構造化質問で補助し、未知の専門的達成条件を断定しない。
3. 既存予定・休息枠・期限・依存関係・本人指定の余裕時間・予算から候補日時を算出。空白を必ず自由時間とみなさない。情報不足時は日付未定案。複数目標の合計負荷と重複を確認。
4. 提案ごとに理由、根拠、前提、不確実性を表示。選択・編集・却下・一括確認後に登録。既存予定を無断変更しない。再提案・再実行で増殖しないID/生成キー。
5. 週次レビューで行動実績・成果測定・遅延を分け、維持/減量/延期/優先順位変更/追加測定を提案。通知は任意、頻度制限、却下後の再通知抑制。目標休止・終了時は未来の生成予定のみ選択して停止、過去実績保持。
6. 将来の端末内AIは候補生成インターフェースのみ差し替え。外部送信や有料APIを必須にしない。金融・健康などは確実な成果を保証しない。

## 画面
- メニューの目標一覧→目標詳細（成果、今週の行動、マイルストーン、見直し）。ホームには任意の次の行動カードだけ。下部5ナビ・配色維持。
- 目標作成は名称→任意の期限/指標→提案選択→予定プレビュー→確定。手動作成・スキップ可能。
- カレンダーは通常予定と目標関連予定を同じ一覧に表示、目標ラベルとフィルタ。日付未定一覧を用意。予定詳細から目標へ戻れる。

## 受入条件
- 既存予定/タスク移行でID・期限・完了・繰り返し・通知保持。旧データの復元と冪等性を検証。
- 目標なし予定、期限と開始の併存、日付未定→日時指定、繰り返し個別完了、取消が可能。
- 提案拒否で予定ゼロ、承認した項目のみ生成、再実行で重複ゼロ。予定衝突・予算不足・未入力・タイムゾーン・期限超過を検証。
- 目標を複数関連付けても家計/時間集計は一度。目標削除/休止で既存予定や実績を暗黙削除しない。
- 成果未測定と行動完了を区別。逆方向指標、目標変更、過去測定値を保持。実機で登録→提案→予定→完了→見直しを確認。
- 無料・オフラインで基本フローが動作。実測とPASS/FAIL/NOT_RUN/BLOCKEDを記録。
