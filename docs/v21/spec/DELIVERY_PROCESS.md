# v12 開発・品質管理（設計承認済み・実装未検証）
## 変更単位
1 課題ID・利用場面・現状証拠・対象版を記録。2 Aの仕様IDとBの受入IDを対応。3 既存処理を調査し再利用を優先。4 最小差分を実装し単体・統合・実機を実行。5 変更前後の画面・操作時間・回帰・復旧手順を記録。6 独立レビューで仕様逸脱と重大欠陥を確認。7 WBS/ISSUES/PROGRESSを更新。未検証はNOT_RUN、障害はBLOCKED。公開版変更・有料契約・保存移行は別承認。
## 管理台帳
仕様ID、課題ID、対象版、現状、変更、変更しない範囲、受入ID、コミット、端末、期待値、実測、証拠、状態、復旧方法。1PRは原則1目的。共通計算・保存変更は全関連画面の回帰必須。UI変更は前後画像、文言辞書照合。自動テスト合格だけで実機合格としない。
## 分割管理
A=製品・体験、B=開発・品質。両方を同じ版で配布。APPROVED_EVOLUTIONはA正本、ROADMAP/QUALITY_GATE/CHANGELOGはB正本。混在資料はファイル単位で保持し参照する。READMEはBに保持、A/BのINDEXに相互参照。片方だけで実装開始しない。更新時は全ファイルの存在、版、参照、承認状態、ZIP破損を検査。30KBは目安、内容を削らない。
