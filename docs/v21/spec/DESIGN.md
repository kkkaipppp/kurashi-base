# 抜本改革設計案
## 根本課題と検証
現行 PLAN100_RESPONSE.md は入力候補、ホーム編集、旅行ID、固定費候補の実装を報告する一方、CSV照合、未接続固定費、設定分割、実機検証を残す。機能追加より、記録負担・判断負担・信頼性の改善を優先する。

|観点|改革|検証|
|---|---|---|
|価値|今日の行動と支出判断を中心に|朝・買物・月末のタスク観察|
|情報設計|ホーム・カレンダー・中央＋・振り返り・メニューの5導線を維持|初見の迷いと戻り回数|
|入力|共通入口、候補確認、取り消し|手入力5秒目標、誤確定ゼロ|
|家計|予算と現金残高を分離、予定と実績を照合|支払済みを二重控除しない|
|統合|生活イベントIDと関連リンク|旅行削除で支出を失わない|
|継続|記録しない日も予定と予算が役立つ|本人4週間、友人β観察|
|アクセシビリティ|文字拡大、読み上げ、キーボード|実機検証|
|性能|大量記録と低容量の試験|10年相当の合成データ|
|安全|移行前バックアップ、復旧、削除確認|障害注入・往復一致|
|運営|無課金・依存先交換可能|費用台帳と代替試験|

## 技術方針
既存 Next.js/Capacitor と schemaVersion 2 を保護。先に保存インターフェースと共通計算を分離し、IndexedDB/SQLiteは試作比較後に採否判断。生活イベントは既存の取引・予定・タスクを参照し、複製しない。固定費は発生回ごとのID、実績リンク、未照合状態を管理。候補は自動確定しない。予測は確定・見込み・不明を区別し、資金残高の入力がなければ残高予測を断定しない。AIは任意の補助で、計算や保存の必須依存にしない。

## 無料制約
利用料・基本運営費とも月0円を目標。静的Web、端末内保存、ローカルOCR、手動バックアップを優先。無料枠・ライセンス・iOS署名・配布条件は未調査。外部API・同期・Watchは費用と実現性を確認し承認まで保留。有料契約禁止。無料枠終了時もデータ書き出しとオフライン利用を守る。
