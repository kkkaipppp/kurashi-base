# 旧くらしカレンダー：画面イメージから再現するUX

`reference_ui/` の4画像をClaude Codeが画像として読み取って比較すること。参考画面は**コンセプト資料**であり完全な画面仕様ではない。DBや色の正確な値、UI座標、CSS値は要求しない。

| 参考画像 | 着目したい体験（色やピクセルは指定しない） |
|---|---|
| `01_old_ui_showcase.webp` | カレンダーで日付→予定/支出へ、日付詳細で予定・支出、支出追加で手入力/画像を選択、レポートの円グラフとカテゴリーが並ぶ |
| `02_v45_ui_showcase.webp` | ホームの予定/残額、カレンダーで予定＋支出の区別、画像確認→修正→保存、週次/月次レポート、固定費の見直し |
| `03_v51_ui_complete.webp` | ホーム「今月あと使える」「今日の予定」、確認したいことはあくまで補助、主要CTAがすぐ分かる、ナビに分析/レポートへの行き先 |
| `04_life_platform_concept.webp` | 生活情報/行動領域を増やしてもホームが散らからない、必要な導線だけ日常UIへ |

## 必須のユーザーフロー
A: 今日の予定を確認 → 予定を追加 → 日時を入れる → 保存 → ホーム/カレンダーに反映。
B: ホームの「今月あと使える」→ 支出の内訳を見る → 支出を編集/削除 → 残額が更新。
C: カレンダーの1日 → 予定、支出、収入が同じ日付に見える。日を切り替えても迷子にならず、選択日に記録追加。
D: 写真/スクショで記録したい → 画像選択 → 画像を見ながら**手で**入力 → 保存（OCR未対応を誤解させない）。
E: 固定費 → 次回の支払い → 記録する → 重複せず次回予定が進む。
F: 振り返り → 月/週の集計 → カテゴリーや日別で変化 → 該当履歴へ。足りないデータは「傾向がありません」と明示し捏造しない。
G: ホームの期限アラート → 何の記録か分かる → 個別項目へ（可能な範囲で編集/完了の行動へ）。
H: 設定 → バックアップ書き出し → 復元プレビュー → 保存前に整合性確認 → 元記録が破壊されない。

## ナビは「最短で何にアクセスするか」で再設計
旧イメージはホーム、カレンダー、レポート/振り返り、＋追加、固定費等の主要行先がわかりやすい。現v2は「ホーム／カレンダー／［＋支出］／取引履歴／メニュー」でレポートが独立しておらず、メニューに17以上の項目が集中。必ずしも旧画像のタブを完全模写する必要はないが、**レポートを発見・参照しやすくすること**と、頻用操作を全画面から迷わず起動できることを最優先する。現在のルート/ブックマーク互換は守る。
