【暮らしベース v2：ユーザー離席中の自律UX改修指示】

現在のリポジトリを対象に docs/ux-autonomous/README.md から全資料を読み、実装・検証・記録まで一気通貫で進めてください。私は外出します。日常的な実装・不具合修正・テスト作成に逐一質問や承認は不要です。ただし環境が権限確認を要求する場合は勝手に回避せず、安全にできるタスクへ進んでください。

【最重要な認識変更】
「前のやつ」とは Phase 1 ではありません。旧『くらしカレンダー』の画面イメージ・操作の軽快さ・日本語・導線を指します。reference_ui/ の旧UI参考4枚を目視で比較してください。添付画像は紹介用参考画面であって、すべての旧実装仕様の証拠ではありません。レイアウト/配色の機械的な模写よりも、見れば使い方が分かる、1～2手で主要操作ができる、家計と予定が同じカレンダーで分かる、気づきや振り返りを得られる、を実現してください。

【依頼】
1. v2の現状コード・画面・docsを読み、`04_GAP_BACKLOG.md`のP0 → P1を実装。現状実装済みなら再実装しない。差分と修正を記録する。
2. `05_SAFETY_REVIEW.md`のデータ保護（特にバックアップ追加復元の参照整合性・復元後の再検証）をUX変更前に修正して回帰テストを追加する。
3. 画面上の自然な日本語を `07_JAPANESE_COPY.md` に基づき揃え、実装しないOCR等が使えるように見える表記を直す。
4. ホーム→予定、ホーム→支出、カレンダー→日付詳細→予定/支出、今月の振り返り→内訳→元の記録、今日のナビ→該当する記録、バックアップ→復元、という流れを、スマホで実操作できるようにする。
5. DBスキーマの再設計、配色の具体値、画面のピクセル配置などは**指定しない**。Claude側で既に保持している設計とコンポーネントを使用する。情報設計上必要なナビ変更は可能だが、既存ルートは維持し、使い手に不利益を出さない。
6. docs/ux-autonomous/06_ACCEPTANCE_SCENARIOS.md をテスト化。最初に `cd app && npm run check` の基準値を保存、変更後も実行。可能であれば画面の自動スクリーンショット（375px/390px）も撮り、画像と見比べる。ブラウザ/実機を利用できないなら NOT_RUN と明記。自己申告PASSは禁止。
7. 長い作業は安全な単位で編集→テスト→コミット（可能なら通常git commit。公開pushは禁止）を繰り返す。クラッシュしても継続できるよう、各単位の完了時に docs/UX_AUTONOMOUS_REPORT.md を更新。
8. 作業開始時と各マイルストンの終了時に親フォルダ（プロジェクトディレクトリの1つ上）へ `00_全体進捗/暮らしベース/` を作成し、`09_RELEASE_ROADMAP.md` と `10_PARENT_WBS.csv` をベースに `ROADMAP.md` と `WBS.csv` の最新版、および `STATUS.md` を同期。親への書き込み権限がなければリポジトリ `docs/parent_progress_export/` にコピーして報告。隣の他プロジェクトには触れない。更新日は事実通り、進捗は実証可能な作業だけDONEにする。

【優先順位】
S0 データ消失/誤復元/誤表示の危険を除去 → S1 旧UIの主要な日常導線へ回帰＋振り返り/レポートの見える化 → S2 日本語、未実装の誤認防止、画面数を増やさず使えるナビへ → S3 他領域の導線とスマホ実用性 → S4 テスト拡充、WBS/報告。
時間や権限で全件終えられない場合、S0/S1を確実に仕上げ、残りは未実装のままWBSに残す。ダミー機能でPASSにしない。

【完成の報告】
(1) 変更したファイル/コミット (2) UX変更のBefore→Afterと画面の証拠 (3) 実テストの結果 (4) 未完/NOT_RUN (5) リリース判定GO/NO-GO（根拠付） (6) 旧UI体験の再現評価（測定根拠付） (7) 親フォルダへのWBS/ロードマップ同期先。
質問待ちで停止せず、安全に確実に進められるものから順に進行してください。
