# 技術レビュー（コード参照・失敗モード・回避策）

## 高：破壊的操作前に修正
- **`app/src/lib/backup.ts:106-139`** 追加復元で参照整合性を検証せずカテゴリ重複IDを無条件に既存優先し、勉強記録ID/資格IDの衝突も考慮しない。**推測される結果：**意味の異なる同IDのカテゴリに取引が紐づいたり、資格記録の参照が変わる。**修正：**衝突テストをまず作成し、キー空間衝突の解決戦略を決め、保存直前のvalidateAppDataと競合プレビューを実装。安全に作れなければmergeを一時無効化。
- **`app/src/app/settings/page.tsx:90-105`** `applyRestore` の返却データを無条件で `replaceAll` に渡す。**修正：**復元元と現データと合成結果を検証、件数/競合を見せて確定前に影響説明。失敗は一切変更なし。

## 中：移行・計算・アラート
- **`app/src/lib/schema.ts:25-33`** v1→v2ですべての新領域のプロパティを空配列に置く。通常のv1では未存在なので意図どおりだが、v1ラベルを残して新領域が既にある異常な/独自ファイルは失われる。**推測：**外部拡張されたデータの破損。**修正：**移行は存在する正しい配列を尊重するか、矛盾検知で明示的に止める。旧版テストを残す。
- **`app/src/lib/schema.ts:73-90`** 旧予定/固定費について必須フィールドに厳格。**推測：**歴史的データに時間フィールドが欠落すると検証失敗の恐れ。**修正：**過去の旧バージョンのバックアップfixturesで実証。安易に規則を緩和しない。
- **`app/src/lib/nisa.ts:27-57`** 現行の基本上限額と翌年の簿価復活は公的制度に概ね一致。**確認対象：**同一年の買付と売却、翌年枠復活、複数年、成長枠上限、保有簿価を超える売却、2024年以前の取得を含めないこと。売却時の入力金額は売却代金ではなく売却口数の**取得簿価**だと明記（`app/src/app/nisa/page.tsx:77-80`）。
- **`app/src/lib/navi.ts:37-47`** 将来の試験を常に1件ずつ表示。**推測：**多数登録時に重要な期限警告が後ろへ流れる。**修正：**緊急度でフィルタ、主たる情報だけ表示し一覧へ到達。
- **`app/src/lib/navi.ts:76-79`** バックアップの必要性が取引/予定だけで判定。**修正：**全領域の入力で対象判定。
- **`app/src/lib/aggregate.ts:50-61`** 繰返し月末/2/29処理あり。**修正ではなく維持確認：**31日→2/28 or 29、年末越え、終了日当日、終了日の前後、週次間隔。仕様で「1回だけ編集」は非対応のまま明示。
- **`app/src/lib/store.tsx:165-171`** 資格を消すとログも同時に消す。意図された仕様だが破壊的。**修正：**対象ログ件数をダイアログで明示し、キャンセル/保存失敗で両方維持されることをテスト。

## Claudeに必須のテスト例
1. IDが同じだが内容が違うカテゴリを含む2バックアップをmerge。誤分類なし/失敗時無変更。
2. ID同じ資格Aと資格Bにそれぞれ勉強ログが紐づくバックアップをmerge。資格とログの参照が不正にならない。
3. mergeで同じ取引IDが既存にもあり、中身が違うケースで競合を説明できる。
4. 復元用JSONが破損、checksum不一致、参照先なし、旧スキーマv1、0件、一部未定義フィールドを含むケース。
5. 保存容量不足時に『保存できた』と見せない。元データ保持。資格削除の取消と保存失敗も検証。
6. NISA: 年末年始/売却簿価/同一年の復活不可/成長枠限度/売却しすぎを確認。
