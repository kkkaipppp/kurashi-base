# 旧UXを意識した日本語修正ガイド

確定した旧版テキストが参照資料内に読めるときは優先。読めないものを「旧版から完全復元」と主張しない。以下は自然な表現の**案**。

| 今の文言 | 直し案 | 意図 |
|---|---|---|
| 今日のナビ | 今日の確認ごと | 必要なら「今日のナビ」を残してよい。見て行動が分かる語にする |
| 残り / 今月の残り | 今月あと使える | ユーザーが使える金額と認識しやすい。ただし予算−支出の定義も小さく明示 |
| 画像から取り込む | 画像を見ながら記録 | 現行はOCR自動読み取りなし。自動取込と誤認させない |
| 取引履歴 | 支出・収入の履歴（画面タイトルは「家計」も検討） | 常用者には「家計」が分かりやすい。ルート互換維持 |
| カテゴリ別の支出 | 何に使った？ / 支出の内訳 | レポートでは質問に答える自然な見出しへ |
| メニュー | すべての機能（見出し） | 多数の機能が隠れることを伝える。タブは「メニュー」のままでも可 |
| NISAの売買の記録を追加 | NISAの買付・売却を記録 | 目的がわかる具体語 |
| 今日の勉強はまだ記録がありません | 今日の勉強記録はありません | やや冗長な文を短縮 |
| 前に登録した記録は変更・削除しません | すでにある記録はそのまま残ります | 安心感と短さ |
| 今のデータを置き換えますか？ | すべての記録をバックアップの内容に置き換えますか？ | 不可逆性が分かる |
| まだ対応していません / 準備中 / 未接続 | 状態別に正しく使い分け | できない操作をできるように見せない |
| 目標・進み X% | 目標：達成率X% | 一読で意味が伝わる |

## 原則
- 画面見出しは短く、説明は使う場面の直前。開発言語・JSON/ID/localStorage等は通常UIへ出さない。
- ボタンは『何が起きるか』で書く。実際の処理を反映し、未実装CTAを置かない。
- 同じ形の選択肢だけ同じ列へ（支出/収入/予定のような同レベル）。
- 必須欄と任意欄を判別可能に。エラーは問題+行動（例『金額を入力してください』）。
- 数字の意味を明記：『今月あと使える』は予算－支出、『NISA売却』の枠復活額は売却代金ではなく取得簿価。
- 日本語だけを理由にバリデーションや保存キー、データ値を書き換えない。
- 実際の画像にある文字が高解像度で判読できないときは不確実として記録し、勝手に断言しない。
