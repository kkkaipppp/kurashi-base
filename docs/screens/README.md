# 画面の記録（版ごとのスクリーンショット）

どんなふうに進んできたかを残すため、**版の区切りごとに、同じ条件で全画面を撮って保存**する。

- 一覧：`docs/screens/index.html`（ブラウザで開く。左が古い版、右が新しい版。画像を押すと大きく表示）
- 条件：iPhone くらいの大きさ（375×812、2倍の解像度）、架空のサンプルデータ（`tools/screens/sample-data.mjs`）と、データなし（はじめて開いたとき）の2通り
- サンプルデータは、撮影用の一時的なブラウザの中だけに入れる。実際の記録・公開の URL には入れない

## フォルダの形
```
docs/screens/
  index.html / index.json        … 全部の版の一覧（gallery.mjs が作る）
  <日付>_<版>_<コミット>/
    manifest.json                … 撮った日・コミット・画面の一覧・撮れなかった画面
    sample/NN_画面.jpg           … サンプルデータあり
    empty/NN_画面.jpg            … データなし
```
画面の番号：01 ホーム／02 ＋（何を追加するか）／03 予定を追加／04 予定の詳細／04b 予定を編集／05 カレンダー／06 振り返り／07 旅行／08 旅行の詳細／09 資格の学習／10 メニュー／11 使い方／12 設定／12b バックアップと復元／13 取引履歴。古い版に無い画面は「この版には無い画面」と表示する。

## 撮り方（版の区切りごと）
1. その版をビルドして起動する（今の版なら iPhone 用サーバー `http://localhost:3211`。PJ_RULES の手順）
2. `node tools/screens/capture.mjs --base http://localhost:3211 --label v5 --commit <短いコミット>`（ほかの大きさは `--width 390 --height 844`）
   - 追加のパッケージは使わない（Windows の Edge をヘッドレスで操作）
   - データ形式1の古い版は `--schema 1`
3. `node tools/screens/gallery.mjs` で一覧を作り直す
4. 画像を何枚か開いて、崩れていないか見てからコミットする

前の版を撮るとき：`git worktree add --detach .wt-screens/<コミット> <コミット>` をプロジェクトの中に作り、`app/node_modules` へのジャンクションを張り、`next.config.ts` の `turbopack` に `root: "C:/Users/kamik/AI開発/暮らしベース"` を足してから `npx next build`（このアプリの Tailwind は Turbopack でしか動かないため。webpack でビルドすると見た目が崩れる）。撮り終えたら、ジャンクションを外してからワークツリーを消す。
