# ロードマップ

日付は開発開始時点で見積もり、完了条件を満たすまで次の段階に進まない。

| フェーズ | 目的 | 完了条件 |
|---|---|---|
| 0. 構想・要件確定 | MVP・対象ユーザー・画面整理 | 要件とモックの対応表、受入条件が揃う |
| 1. 技術検証 | 保存・OCR・iOS連携の実現性確認 | 動く試作と制約・費用・代替案が記録される |
| 2. 基盤構築 | 新規リポジトリ、データ設計、CI | 基本画面と自動テスト基盤が動く |
| 3. MVP開発 | 家計・予定・ホーム・取込・保全 | 主要フローが動作する |
| 4. 品質保証 | E2E・データ保全・UI検証 | リリースゲートを満たす |
| 5. 招待制ベータ | 実利用から問題を把握 | 重大問題の修正、継続利用の確認 |
| 6. 一般公開判断 | 運用・費用・プライバシーを評価 | 公開可否を明示的に決定 |
| 7. 領域拡張 | 12領域へ段階的に拡張 | 利用価値・技術基盤・保守性を確認 |

優先順位は「日常で使える基盤」→「自動化」→「領域拡張」。全機能を同時に実装しない。
