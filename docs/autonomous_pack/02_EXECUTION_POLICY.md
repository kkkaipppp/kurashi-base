# 自律実行ポリシー

## 判断と進行
- 作業開始時にgit status、既存ドキュメント、現行コード、テストコマンドを確認する。
- 現状の動作を正本とし、仕様との差異は `docs/FEATURE_BOX_STATUS.md` に記録する。
- 安全な実装判断は自律で行い、細かい質問で止まらない。判断理由を記録する。
- 小さな単位で実装→テスト→修正を繰り返す。各段階で動く状態を維持する。
- 作業時間やコンテキストが足りなくなったら、次に続けられる `docs/NEXT_SESSION_HANDOFF.md` を作る。

## 優先順位
1. 既存機能とユーザーデータの保護
2. P0の10領域の到達可能な箱、うち基本操作指定の領域は動作する最小CRUD
3. 全画面の自然な日本語化
4. P1のうち既存機能に自然に追加できるもの（繰り返し予定、週次固定費、返金等の入口、OCRの試作）
5. PWA・ウィジェットプレビュー等は安全にできる範囲のみ

## 禁止・停止条件
- 既存の保存データを消す・スキーマを非互換変更する・既存コードを全面置換することは禁止。
- 本番デプロイ、外部API接続、実アカウント作成、課金、外部送信、秘密鍵操作、無断のgit pushはしない。
- 破壊的変更が不可避な場合は実施せず代替案を記録する。
- テストが落ちた場合は修正を優先。修正できない場合は不合格として記録し、成功を装わない。
- ユーザー不在でも安全に進められる範囲まで進め、止まった理由と再開手順を残す。

## 必須成果物
`docs/FEATURE_BOX_STATUS.md`, `docs/JAPANESE_COPY_AUDIT.md`, `docs/TEST_REPORT.md`, `docs/NEXT_SESSION_HANDOFF.md`。
可能ならスクリーンショットと、画面・操作一覧も追加。
