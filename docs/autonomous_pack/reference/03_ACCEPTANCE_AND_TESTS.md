# 受入基準とテスト方針

## P0 回帰（最優先）
- 既存の家計登録/編集/削除、集計、予定、固定費、取込、バックアップが継続動作する
- データの初期化・消失・既存ユーザーデータの上書きが起きない
- 既存 `npm run check` が通る。失敗したら原因を直し、結果を報告する

## 箱ごとの共通テスト（10領域すべて）
- 入口から開ける、戻れる、空状態が読める、未実装機能が未実装と分かる
- 保存できる箱は、追加→一覧→編集→削除/完了→再読み込みの確認
- 入力の必須チェックとキャンセルができる
- スマホで操作が途切れない（狭い幅・キーボード表示時）

## 個別テスト
- タスク: 完了/未完了の切替、期限未設定、期限超過の表示
- 資産: 数値入力、評価額未設定の状態
- 契約: 更新日未設定/経過、解約済みの扱い
- 生活記録: 日付ごとの記録
- 健康: 記録は診断ではないことが分かる
- 目標: 進捗0/100、期限未設定
- 共有: 招待を送信したと誤表示しない
- AI: AIが応答したと偽装しない
- 外部連携: 接続完了と偽装しない
- 書類: ファイル未保存の場合は保存済みと偽装しない

## テスト結果の報告
PASS/FAIL/NOT_RUN を明記し、実行していないテストをPASSとしない。既存の120件カタログは回帰観点として参照し、初回から全件実行は要求しない。
