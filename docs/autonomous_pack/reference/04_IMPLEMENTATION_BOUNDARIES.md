# 実装境界・進め方

1. 作業開始時に現行アプリのコード・既存のClaude側資料・ルーティングを確認し、現行の事実を優先する。
2. 既存機能を作り直さず、拡張として実装する。不要な大規模リファクタリングは避ける。
3. DB・保存方式・データモデル・配色・配置・コンポーネント設計はこの資料で指定しない。Claude側の既存設計に従う。
4. まずP0の箱を揃える。P1/P2は入口・制約説明までで止めてもよい。
5. 非対応のOS機能はできると断言しない。iOSウィジェットや他アプリ通知自動取得は別途技術検証。
6. 既存ユーザーデータを消す変更は行わない。破壊的な変更が必要なら作業停止し承認を求める。
7. 完了後に `docs/FEATURE_BOX_STATUS.md` を作り、機能ごとに 実装済/箱のみ/未実装、検証結果、次の改善案を記録。
8. 仕様を過剰に深掘りしない。ユーザーと次フェーズでブラッシュアップする前提で、触れる骨格を優先する。
