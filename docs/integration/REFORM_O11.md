# 98810b7 統合・抜本改革指示（o11）
最新版を正本とし、o10までの採用済み設計を統合する。旧版の全置換は禁止。公開・push・費用・外部送信は別承認。現行Phase 0–6、既存WBSに統合する。
## 実装順序と停止条件
1. 現行の全画面・保存・計算・ネイティブ境界の依存図を実コードから作成。最新コミットと既存テストを基準化。差分表の要確認項目を解消。
2. 共通台帳を設計。口座・カード別開始債務、購入・返金・決済・振替の独立イベント。現行 refundGross/refundWas/cardDebt を失わない。未知の開始債務はゼロと断定しない。購入日・返金日・現金移動日を分離。
3. Repository境界と原子的更新。Web IndexedDB、iOSは実際のCapacitor/Swift構成確認後に保存方式を選択。移行前バックアップ、検証、切替、失敗時旧データ維持。旧形式への書き戻しは新規記録を失わない場合のみ。
4. 新旧計算を並行比較し、差分を説明。固定費・予測・予算・旅行・資格・資産を同じ台帳へ接続。過去月・未来月・複数カード・返金順序・基準日を試験。
5. UI o10基準を全画面へ適用。本文16px、補足13px、ナビ12px、主要操作48px、タップ44px、余白16px、320px/200%/VoiceOver/長文/大金額を実機検証。既存5ナビを維持。日本語は金額の意味を区別。
6. 事業戦略は設計を保持。広告は承認までOFF、個人版なし、外部送信なし。商用ホスト・規約確認を別ゲートにする。
7. npm run check、公開/個人ビルド、実機、30年データ、移行中断、容量不足、競合、復元試験。重大欠陥があれば停止。最新GOを再判定。WBS/ISSUES/STATE/DECISIONS/RAIDを更新し同期。
## 統合上の注意
最新版のカード基準債務と返金控えの実装は旧o9より優先。旧テストの期待値はそのまま採用せず現行仕様と照合。参考資料は docs/integration/o10-reference に格納。今回の統合は全面刷新の完了ではない。全体試験未実施。
