## 3. 容量
- **公開版（localStorage・約500万字）**
  - ふつうの保存：8年分（約450万字）までは入り、9年分は入りません。
  - 取り消し用の控えを書く操作：4年分までは入り、5年分から入りません。控えを書く操作は、バックアップからの復元、CSV やカレンダーの取り込み、未整理の記録のまとめた変更、取り込みの取り消し、旅行の複製、カテゴリをまとめる操作です。
  - 入らないときは「保存できない」と言い、前の記録と控えはそのまま残ります（試験済み）。

  - 自動バックアップ：16.6MB（上限 50MB）

## 4. 直さずに記録するもの（設計の指摘）
- 保存のたびに全体（30年分で約17MB）を書きます。控えつきの保存では、さらに同じ大きさを書きます。
  - IndexedDB の版を比べるために、本体を読んでいます。
  - 記録を分けて保存する形（collection ごと）にすると軽くなりますが、保存の形を変えることになるので、今はしません。
- 自動バックアップは、アプリを裏に回すたびと前に戻すたびに、全体を JSON にして iPhone アプリへ渡しています。
  - 中身も日付も前に書いたときと同じなら、渡さないようにしました（自分用）。ただし、これは1回の起動の中だけです。アプリを起動するたび（画面の読み込み直しも含む）に、1回は全体を書きます。
  - 記録がいちばん多かったときの控えは、今までどおり、件数がこれまでの最多と同じか多いときに書き直します。一度「1日1回まで」にしましたが、その日に足した記録が、どの自動バックアップにも残らない道ができたので戻しました（点検2回目 中-1）。
- 裏に回したとき、JavaScript 側の準備が終わってから、iPhone が書き込みの時間をもらう手続きをします。そのため、大きいデータでは書き終わる前に止められる可能性があります（DEVICE_PENDING）。
- 測る画面は、画面と同じ処理の流れで動きます（別の処理の流れは使っていません）。30年分の前には確かめを出し、30年分は1回ずつ測ります。
