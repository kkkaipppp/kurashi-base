## 守ること（安全・承認。指摘を理由に緩めない。範囲と理由を添える＝プレイブック 9-3）
- `00_受領資料/` と `docs/ux-autonomous/`・`docs/autonomous_pack/` の既存のファイルは書き換えない（要件の原本のため。新しく受け取った資料は、日付つきのサブフォルダとして足してよい）
- `00_経営管理` とほかのPJのフォルダには書き込まない（ほかのPJの持ち物のため。例外：ユーザー指示の `../00_全体進捗/暮らしベース/` への進捗同期。読むだけはよい）
- 外部の有料API・秘密鍵は使わない。ユーザーのデータを外部へ送らない（個人の家計・予定のため）
- **npm パッケージ・Python ライブラリの追加と、外部からの大きなダウンロード（OCR の評価用画像など）は、何をどこから入れるかを伝えて OK をもらってから**（全体の CLAUDE.md の決まり。依存とライセンスが増えるため）
- git の push・公開・本番配布は、ユーザーの OK をもらってから（URL を知った人に届くため）
- ユーザーのデータ（localStorage）を消す・形式を互換性なく変える変更はしない（記録は端末の中にしかないため）。形式を変えるときは `schema.ts` の `migrate()` とテストを先に書く。**例外**：アプリ内ブラウザの開発用の origin（localhost）に自分が入れたテスト用データは、確認のあと自分で消し、消したものを報告する（下の「確認の手順」。前からのこのPJの決まり）
- 片付け（プレイブック 12-1・12-5、2026-11-22 ユーザー決定）：Claude が自分で作った一時ファイルは、要るものが混ざっていないかを見てから**ごみ箱へ移し**、移したものを報告する。ユーザーに渡したファイル（`_review/` の ZIP・依頼文など）・ユーザーが作ったファイル・誰が作ったか分からないもの・完全に消す操作は、ユーザーの OK をもらってから
- テスト未実施を PASS と書かない。実機で見ていないものは「実機は未確認」と書く
- ファイル名（プレイブック 12-7、2026-11-22 ユーザー指示）：Claude や ChatGPT が作って平尾さんとやり取りするファイルは `kurashi-base_<対象>_<内容>_<コミット7桁か YYYYMMDD>.<拡張子>`。対象＝何のためか（`review-uiux`・`review-code`・`release`・`feedback` など）、内容＝中身（`zip`・`request`・`report`・`patch` など）。例：`kurashi-base_review-uiux_request_c721b69.txt`。ChatGPT などほかの AI に作らせて返してもらうファイル（レビューの ZIP など）は、依頼の版も名前に入れる（例：`kurashi-base_review-uiux_result_c721b69-o2.zip`、o2＝依頼文の2版目。プレイブック v1.3.8）。同じ名前があれば上書きせず版を上げる。アプリのコード・ツールが名前を決めるもの（`package.json`・`report.json` など）はそのまま

## UX の基準
- 「前のやつ」「以前の画面」は、旧『くらしカレンダー』の画面イメージ・操作感を指す（Phase 1 ではない）。参考画面：`docs/ux-autonomous/reference_ui/` の4枚。画面を大きく変える前に見比べる（LESSONS L-05）
- 体験の原則：起動して3秒で「今月の残り予算」「今日の予定」「今日やること」が分かる（v5）／主要な記録は1〜2操作／予定とお金を同じカレンダーで見る／振り返りで気づきが得られる
- 使えない機能（OCR・同期・AI・共有・ウィジェット）を、使えるように見せない

## 文言チェック（選択肢・ラベルを足すとき。LESSONS L-04）
1. 選択肢は同じ種類・同じ粒度・同じ形の言葉で並べる。種類が違えばグループに分ける
2. 欄の名前：物は「名前」、タスク・目標は「内容」、メモ・予定は「タイトル」
3. チェック欄は短い名詞（完了・達成・上に固定・有効・終日）
4. 任意の欄は `optional` の印（ラベルに「（任意）」と書かない。テストで検査）
5. 画面名は短い名詞。正式名は説明文へ。メニューは中身の種類で分け、状態（準備中）はグループにしない
詳しいルールと修正の履歴：`docs/JAPANESE_COPY_AUDIT.md`

## 確認の手順
- 自動：`cd app && npm run check`（型・lint・テスト・ビルド）
- 画面：アプリ内ブラウザでモバイル幅（375px）。全画面を 320/375/390px で横はみ出しなし
- **iPhone 実機でしか出ない問題がある**（日付・時刻の欄、キーボード、http での制限。LESSONS L-01〜03）。入力部品やシートを変えたら、実機での確認をユーザーに頼む。直したら「実機で直ったか」まで確かめて完了にする（L-08）
- **合格の記録には日時（またはコミット）を付ける。公開・友人に渡す前に、その合格が「最後に変更した日時より後」に付いたものかを確かめる**（古い合格のまま渡さないため。プレイブック L12、2026-11-22 点検役の指摘から）
- 画面確認で入れたテスト用データは、確認のあと必ず消す
- **画面の記録**：版の区切り（ZIP をレビューに出すとき・公開するとき）ごとに、`node tools/screens/capture.mjs` で全画面を撮り、`node tools/screens/gallery.mjs` で一覧を作り直す（進み具合を残すため。2026-11-22 平尾さんの依頼。手順は `docs/screens/README.md`）

## iPhone 用サーバー（同じ Wi-Fi の中だけ。LESSONS L-07）
1. `cd app && npm run build`（`npm run check` に含まれる）
2. ポート 3211 を使っているプロセスを止める（タスクを止めても残ることがある）
3. `cd app && npx next start -H 0.0.0.0 -p 3211` をバックグラウンドで起動
4. `curl` で `http://<PCのIP>:3211/` と新しい画面が 200 になるか確かめる
5. iPhone で開けない（黒い画面のまま）ときは、iPhone の Wi-Fi を **XN-002-5G** にする。XN-002（2.4GHz）では端末どうしがつながらないことがある（LESSONS L-10）

## ユーザーへの頼み方（プレイブック 7章・10章 L1/L2）
- **ユーザーへの返信は、途中の短い一言も含めて、すべて日本語で書く**（まとめ欄・本文・背景の作業を待つ一言・ツールの結果の直後の一言・ほかのセッションへの返事のあと）。英語の決まり文句（"running in the background" など）を書きそうになったら、日本語で書き直す（全体の CLAUDE.md の決まり。LESSONS L-09・L-11）
- **ツールとツールの間の一言は、作業メモではなく平尾さんへの返信**。必ず日本語の型で書く：「〜しています。」「〜を確かめます。」「〜が終わるのを待っています。」。要らない一言は書かない。英語で1文でも書いてしまったら、次の一言で日本語で言い直す（LESSONS L-12、3回目）
- Claude ができることは自分でやる。ユーザーに頼むのは、iPhone の実機操作・判断・公開や送信の最終確認だけで、1回にまとめる
- 実機確認を頼むときは、**1行目に開く URL だけ**を書く（LESSONS L-06）
- 選択肢には①②③の番号を付け、推奨を①にする。判断は1回に1つ
- 「できました」は証拠（テスト・画面・実機）とセットで
- 「前のやつ」「以前の版」など、どれを指すか分からない言葉が出たら、どの版・どのファイルかを①②③で確かめてから作業する（プレイブック L10・LESSONS L-05）
