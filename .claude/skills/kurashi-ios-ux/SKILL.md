# 暮らしベース：iPhone と画面の確かめ方

## 現行の形
- Web 版（Next.js、公開版は Vercel）と、自分用の iPhone アプリ（`feat/ios-widget`、Capacitor 8.6.0 と WidgetKit のウィジェット。Mac からの入れ直し）。
- 体験の原則・言葉の決まりは PJ_RULES の「UX の基準」「文言チェック」が正本。使えない機能を使えるように見せない。

## 確かめ方（PJ_RULES「確認の手順」）
1. `cd app && npm run check`。言葉と見張りのテスト（`app/tests/copy-v5.test.ts`・`app/tests/lessons-guard.test.ts`）が通ること。
2. アプリ内ブラウザで幅 320/375/390px、横にはみ出さない。入れたテスト用データは確認のあと消す。
3. 見やすさ：本文の文字のコントラスト 4.5:1 以上、文字以外の大事な部品は 3:1 以上、色だけで意味を伝えない（デジタル庁デザインシステムをもとにした社内の基準。認証ではない）。
4. iPhone 実機でしか出ないもの（日付・時刻の欄、キーボードで隠れる、http での制限：LESSONS L-01〜L-03、L-10）を変えたら、実機の確認を平尾さんに頼む。頼むときは1行目に開く URL だけ（LESSONS L-06）。直したら実機で直ったかまで確かめて完了にする（LESSONS L-08）。
5. 実機で見ていないものは「実機は未確認」（DEVICE_PENDING）と書き、PASS にしない。合格には日時かコミットを付け、最後の変更より後の合格かを確かめる（PJ_RULES「確認の手順」）。
